Chapter 1

The startup lifecycle, rebooted for 2026

AI 没有让创业变成另一件事；它改变的是创业路径的成本结构。过去需要团队、融资和长周期的任务，现在可以由创始人直接编排 AI 系统完成。

Idea

先验证问题是否值得做。AI 是研究伙伴和反方辩手。

MVP

把问题转成最小产品。AI 是工程团队，但必须被上下文约束。

Launch

把 traction 变成业务系统。AI 帮你跑运营、合规和产品流程。

Scale

让组织成熟并形成护城河。AI 沉淀数据、工作流和领域上下文。

AI 可以写生产代码、做市场研究、合成竞争格局、起草投资人材料、自动化运营流程。它真正压缩的是从想法到产品、从产品到业务、从业务到组织的距离。

传统路径默认创业会经历验证、融资、招人、构建、再融资、增长、继续招人。手册给出的新路径，是把每个阶段重新定义成“证据门槛”。进入下一阶段的依据不是团队人数，而是你是否拿到了足够证据。

新的瓶颈不再是“能不能做出来”，而是“该不该做、先做什么、何时停止”。
Core shift

AI 原生创业不是传统公司加 AI 功能，而是从第一天把 AI 当作研发、研究、运营和组织基础设施。

Chapter 2

What it means to be a founder is changing

过去创始人的分工常常被技能边界决定：技术创始人写代码，非技术创始人负责销售、运营和融资。AI 让这个边界变薄。非技术创始人可以交付生产软件，技术创始人也可以借助 AI 补齐 GTM、财务模型和投资人材料。

创始人的角色从 individual contributor 变成 agent orchestrator。你的注意力不再主要消耗在亲手执行，而是用来生成想法、设定约束、组织 AI agent 和小团队完成工作。

AI tool capabilities for lean startups

CapabilityThinkUse
Conversational intelligenceon-call expert研究、分析、战略推演、文档
Agentic codingalways-available engineer生成、测试、调试、重构产品代码
Workflow automationautomated ops teamCRM、周报、日程、文档、跨系统同步

早期 AI 原生公司可以极度精简，但不是因为“人不重要”，而是因为 AI 承担了过去大量需要职能团队才能完成的工作。创始人要做的是掌握时机和编排。

Founder leverage

AI 让创始人池扩大：有行业经验和真实痛点的人，即使没有工程背景，也能开始构建可运行产品。

Chapter 3

Idea Stage

Idea 阶段不是开始写代码，而是证明问题值得做。AI 越能降低构建成本，创始人越需要先验证。

Goal

这个阶段的目标是 research-oriented validation：收集证据，证明真实问题存在，并且你的方案确实解决了验证后暴露出来的问题。

  • 问题是否真实、具体、足够频繁？
  • 到底是谁有这个问题？这是否构成市场？
  • 谁已经在解决？解决得好不好？
  • 方案真正需要做什么？你的想法是否满足？

Exit criteria

退出条件是 problem-solution fit。你能明确说出谁遇到问题、痛感多强、现在怎么处理、你的方案为什么解决真实问题，并且有足够定性证据进入 MVP。

Challenges

Mistaking building for validating

AI 让原型很容易出现，但原型不是市场证据。它只是用户访谈中的道具。

Premature scaling

AI 会围绕错误前提同样积极地构建系统。创始人的 sense-making 必须领先于 building。

Loss of objectivity

让 AI 支持你的观点，它会找到材料。更好的用法是让它寻找反证和失败案例。

How Claude helps

用 Chat 做快速思考，用 Claude Cowork 做研究和文档，用 Claude Code 在阶段末尾构建轻量 prototype。

Exercises
  • 把模糊问题改成可测试假设。
  • 让 Claude 写出最强反方论证。
  • 按直接、间接、相邻、潜在进入者绘制竞品地图。
  • 每五次访谈后，分别列支持证据和反对证据。
  • 只构建一个核心交互，拿给 5 个目标用户试。
Prime directive

先验证假设，再构建原型；原型服务于对话，不替代对话。

Chapter 4

MVP Stage

MVP 仍然是证据收集阶段，只是证据对象从问题转为解决方案。你要证明用户会回来、付费或推荐。

Goals

把已验证问题转成真实用户可用的最小产品；快速推进，但不积累会在真实用户到来时爆炸的技术债；从第一天建立持久上下文。

Exit criteria

退出条件是真实 PMF 证据：可识别的一群用户从产品中获得足够价值，表现为 retention、revenue 或 referral。

Challenges

Agentic technical debt

AI 技术债会复利。没有规格和架构约束，每次会话都会重新推断基础决策。

False product-market fit

朋友试用、一次传播和早期热闹不等于 PMF。要看第 6 周和第 12 周后用户是否还回来。

Zero-friction scope creep

功能越容易加，越需要书面范围定义。新增功能必须由真实用户证据触发。

Insecure by inexperience

能跑不等于安全。上线给真实用户前，至少要做认证、权限、API 暴露、输入校验和依赖审查。

Exercises
  • 写下未来 6 个月的架构约束并保存为 CLAUDE.md。
  • 上线前定义留存、激活和假阳性指标。
  • 三轮迭代无 PMF 进展时，让 Claude 判断是细分用户、定位还是产品问题。
Session loop

每次 Claude Code 会话前加载上下文和范围；会话后更新决策日志。五分钟文档化，换来长期系统一致性。

Chapter 5

Launch Stage

MVP 证明产品值得存在；Launch 要证明业务值得增长。创始人必须从亲自抓每条线，转向设计能运行的系统。

Goals and exit criteria

ExitMeaning
Repeatable growth渠道可解释，CAC、LTV、payback 可 defend
Production workloads基础设施、安全、合规、可靠性经得起真实流量
Operations without bottlenecks支持、分流、冲刺、报告不靠创始人亲手处理

Challenges

技术债开始到期；创始人从资产变成瓶颈；安全合规不可再推迟；过早进入新市场会稀释原有 PMF 并让数据不可解释。

How Claude helps

  • Claude Code 做架构审计，找脆弱点、重构候选和测试缺口。
  • Claude 排序修复工作，区分必须立即处理、可并行、可暂留。
  • Claude Cowork 审计创始人运营负载，设计自动化和委派流程。
  • Claude Code + Claude 共同处理安全、合规、审计日志、访问管理和文档。
  • Claude 设计轻量产品管理系统，Claude Cowork 跑周期性元素。
Exercises
  • 列出所有只有创始人知道答案的支持和运营流程。
  • 做一次技术债审计并排三个 sprint 的修复顺序。
  • 设计 sprint cadence、spec template、bug triage tree 和 weekly metrics brief。
Launch mindset

找到 PMF 很难；保住 PMF 同样难。Launch 阶段的失败，常常不是产品没人要，而是组织跟不上。

Chapter 6

Scale Stage

Scale 阶段，创始人从 builder 转为 public-facing executive。产品仍是中心，但公司本身开始接受更严肃的外部审视。

Goals

从几千用户到数百万用户，从一个市场到多个市场。目标是建立系统性增长、成熟组织运营，以及能经受投资人、监管、企业采购和并购方审查的公司。

Exit criteria

Scale 的退出是阈值事件：公司不再依赖创始人亲自跑日常，增长可审计，治理和合规成熟，并且面对资源充足的 incumbent 复制时仍有留住用户的理由。

Challenges

  • 把运营层交出去，并让系统真的可靠。
  • 把技术运营升级成企业级基础设施。
  • 补齐财务、合规、合同、客户支持等组织函数。
  • 建立真正 GTM，而不是继续依赖 founder hustle。

How Claude helps

Claude 帮你定义创始人必须保留的工作；Claude Cowork 承接日常运营；Claude Code 构建支持基础设施、集成、API、webhook、demo environment 和 observability。

MoatHow it compounds

Exercises
  • 做 bottleneck map：创始人消失一周，哪些流程会停？
  • 选三个最挑剔的企业客户，列出他们签多年合同前会要求的文档、SLA 和支持系统。
  • 审计前十个客户的集成深度和切换成本。
Defensibility

功能领先会被追上。领域上下文、行为数据和工作流嵌入，才是更难复制的 AI 原生护城河。

Chapter 7

Same job, new rules

创始人的工作没有变：找到真实问题，构建解决方案，扩张成有意义的公司。变的是路径。

验证周期从月压到天，prototype 不再要求合适技术联合创始人，launch readiness 从上线前冲刺变成持续工作流，scale 阶段的运营重量也可以被 AI 承担一部分。

The bottlenecks are no longer what you can build, but what you choose to build.
